# Full agent-workflow acceptance

The goal remains: a user supplies several HWP/HWPX files and edit instructions; Codex or Claude edits through browser computer use, checks saved editable results and returns them with source structure preserved, without routine foreground/native Hancom interaction. A passing subset does not complete this goal.

This is the requirement checklist as of 2026-10-10. Detailed evidence and earlier checkpoints are in `verification.md`. Local reports and real-browser artifacts are deliberately ignored by Git because document-derived evidence may be private.

| Requirement | Evidence now | Completion boundary |

The current build passes 197 checks across ten suites. Nested movement, cutting and transposition use full paths. Browser clipboard events and edit-menu cuts remove the selected inner table and preserve its enclosing content. Recovered paste retains table geometry, cell properties and text across repeated reloads without a full-file export during typing. Logical undo handles remain valid when a new journal continues a replayed prefix. Whole-table transpose retains cell-zone ranges; partial paste retains destination-cell properties. Find releases a previous cell block, and overflow preflight avoids poisoning the recovery journal through an attempted out-of-bounds paste. Before unload, the host checks the live journal revision rather than relying only on a queued status notification. Actual hidden-browser HWP and HWPX transpose, immediate typing, undo/redo, recovery, saved export and disk reopening have been verified. A visual comparison exposed overlapping host text in the synthetic original and border crossing after transpose; this remains an active rendered-flow boundary. Continue with that boundary, caption routes, special-object editing/preservation and exact-source native fidelity. Establish failing reproducers before changing those routes; do not disable requested functionality or redefine the goal to the already passing cases.
